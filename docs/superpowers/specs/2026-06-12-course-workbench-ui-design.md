# 课设通前端工作台设计文档

## 1. 设计目标

本次前端模块的目标，是将现有的后端能力整合为一个可直接演示和可直接操作的“课设通 Agent 助手工作台”。

界面风格参考 Codex 桌面端，强调以下特征：

- 深色、克制、专业、工具化
- 多面板协同，而不是单页聊天机器人
- 适合持续工作，而不是一次性问答
- 能同时承载对话、任务、产物和审查结果

该前端应明显体现“课设工作台”定位，而不是普通 AI 聊天网页。

## 2. 核心设计原则

1. 页面默认进入工作台视角，而不是单一聊天视角。
2. 用户的核心任务不是“闲聊”，而是“完成课程设计”。
3. 中央主工作区负责输入与生成过程。
4. 右侧结果区负责沉淀结构化成果。
5. 左侧导航区负责模式切换和上下文入口。
6. 界面交互要尽可能接近桌面开发工具的连续工作感。

## 3. 布局方案

采用三栏布局。

### 3.1 左栏

左栏作为导航与上下文入口，包含：

- 品牌区：课设通 Agent 助手
- 模式导航：
  - 课设对话
  - 完整方案
  - 产物生成
  - 方案审查
- 最近请求记录
- 快捷操作按钮

左栏视觉上保持收敛，宽度稳定，不因内容长度变化而跳动。

### 3.2 中栏

中栏作为主工作区，承担输入、流式生成和主任务交互。

中栏内容结构：

- 顶部上下文条：
  - 当前课设题目
  - 当前技术栈
  - 当前模式
- 主输入区：
  - 题目输入
  - 技术方向
  - 技术栈
  - 附加要求
- 提交区：
  - 发送按钮
  - 生成按钮
  - 清空按钮
- 流式输出区：
  - 普通对话输出
  - 完整方案生成过程
  - 单产物生成结果
  - 审查结果输出

中栏是整页的视觉中心。

### 3.3 右栏

右栏作为结果沉淀区，负责展示结构化成果。

右栏内容结构：

- 当前请求摘要
- 结构化结果目录
- 结果切片展示：
  - 数据库设计
  - 接口设计
  - 项目结构
  - 报告大纲
  - 测试用例
  - 答辩准备
- 一键复制当前内容
- 状态提示：
  - 处理中
  - 已完成
  - 失败

右栏内容需要支持长文本滚动，但右栏自身宽度保持稳定。

## 4. 模式设计

工作台支持四种核心模式。

### 4.1 课设对话

对应后端接口：

- `/api/course_chat`
- `/api/course_chat_stream`

适合自由提问、连续追问、多轮上下文对话。

### 4.2 完整方案

对应后端接口：

- `/api/course_project`
- `/api/course_project_stream`

适合输入课设题目后生成一整套方案。

### 4.3 产物生成

对应后端接口：

- `/api/course_project/artifact`

适合单独生成：

- 数据库设计
- 接口设计
- 项目结构
- 报告大纲
- 报告正文初稿
- 测试用例
- 答辩问答

### 4.4 方案审查

对应后端接口：

- `/api/course_project/review`

适合对已有方案内容做完整性检查与修改建议。

## 5. 默认交互路径

首页默认进入“混合工作台”状态。

默认交互路径如下：

1. 用户在左栏选择模式
2. 用户在中栏填写题目、方向、技术栈与要求
3. 用户发起请求
4. 中栏展示流式生成过程
5. 右栏同步沉淀结构化结果
6. 用户可在右栏查看单独产物，或复制结果继续使用

这种路径强调“生成过程”与“结构化结果”并行展示。

## 6. 视觉风格要求

整体采用深色工作台风格。

### 6.1 色彩

- 深色背景为主
- 低饱和边框
- 亮色仅用于焦点、状态和激活项
- 不使用营销型渐变大背景

### 6.2 组件风格

- 小圆角
- 稳定边框
- 按钮以图标或图标+文字为主
- 面板不使用大卡片堆叠
- 页面布局尽量贴近桌面开发工具

### 6.3 文字与密度

- 标题克制，不做网页式大 Hero
- 信息密度适中，便于扫描
- 长内容区域需支持 Markdown 样式展示

## 7. 技术实现方案

本阶段前端不引入新的前端框架，优先基于现有 Spring Boot 静态资源实现。

建议文件结构：

- `src/main/resources/static/index.html`
- `src/main/resources/static/app.css`
- `src/main/resources/static/app.js`

这样可以：

- 与当前项目基线保持一致
- 减少构建复杂度
- 更快进入可演示状态
- 便于后续继续演进

## 8. 状态管理策略

前端需要保存以下状态：

- 当前模式
- 当前题目
- 当前技术栈
- 当前附加要求
- 当前会话 ID
- 当前请求 ID
- 当前主输出内容
- 当前结构化结果面板内容

状态优先使用原生 JavaScript 管理，不额外引入复杂状态库。

## 9. 错误处理

前端需要统一处理以下错误：

- 请求参数为空
- 后端接口失败
- 流式连接中断
- DashScope 未配置
- Milvus 相关能力不可用

错误提示要求：

- 全部中文
- 就近显示
- 不遮挡主内容
- 错误后仍保留用户已填写的表单内容

## 10. 联调目标

该前端模块完成后，应满足以下目标：

1. 可直接在一个页面完成课设对话
2. 可直接生成完整课设方案
3. 可直接单独生成课设产物
4. 可直接审查现有课设方案
5. 可展示流式结果
6. 整体 UI 气质明显接近 Codex 桌面端工作台

## 11. 本阶段不做的内容

为控制范围，本阶段不包含以下内容：

- 新前端框架迁移
- 登录系统
- 多用户数据持久化
- 真正的会话历史数据库
- 文件管理系统
- 复杂拖拽布局

本阶段重点是“工作台成型”和“能力可演示”。

## 12. 后续衔接

该前端模块完成后，下一步自然进入联调与验收阶段，重点验证：

- 对话模式是否稳定
- 完整方案模式是否结构清晰
- 产物生成是否可复用
- 审查结果是否有指导价值
- 前端展示是否足够支撑课程设计演示
